This page organizes the documentation by task. It does not replace the configuration reference; it helps you decide which page to read first and what each section is meant to answer.

<Aside type="tip">
For a first deployment, follow the deployment path. For an existing service, jump directly to the task cards below.
</Aside>

## Reader Paths

<Tabs syncKey="reader-path">
  <TabItem label="Deployer" icon="rocket">
    **First-start loop**: Complete [Quick Start](../quick-start/) with single-node production Compose. Success means `.env.postgres` and `.env.synctv` are preserved, `/health/ready` succeeds, and the root user can log in.

    **Production hardening**: Use the [Production Checklist](../../deployment/production-checklist/) for TLS, backups, metrics, alerts, and upgrade planning. Read [Docker Compose Deployment](../../deployment/docker-compose/) when you need file, volume, and port details.

    **Understanding and expansion**: Read [Architecture Overview](../architecture/) for service, management, metrics, Redis, PostgreSQL, and provider proxy boundaries. When changing configuration, use [How Configuration Works](../../configuration/how-configuration-works/), the [Configuration Index](../../reference/configuration-index/), and [Full Configuration Example](../../configuration/full-example/).

    **Multi-replica and operations**: Only move to [Helm Deployment](../../deployment/helm/) and [Cluster Configuration](../../configuration/cluster/) when you need Kubernetes or multiple replicas. After launch, use [Backup and Restore](../../operations/backup-restore/), [Upgrades and Migrations](../../operations/upgrades/), [Observability Runbook](../../operations/observability/), and [Troubleshooting](../../operations/troubleshooting/).
  </TabItem>
  <TabItem label="Administrator" icon="setting">
    <Steps>
      1. Read the [CLI Reference](../../reference/cli/) for users, rooms, providers, system state, and configuration validation.
      2. Read [Administration Runbook](../administration/) to understand operational boundaries for users, rooms, reviews, providers, runtime settings, and system operations.
      3. Read [Rooms, Permissions, and Preferences](../rooms-permissions/) to understand global roles, room roles, permission bits, room settings, and user preferences.
      4. Read [Authentication and Security Model](../security-model/) to understand local login, OAuth2, 2FA, tokens, and the management control plane.
      5. Read [Runtime Settings Reference](../../reference/runtime-settings/) to know which policies are hot-reloadable and which require startup configuration.
      6. Read [Email and OAuth2](../../configuration/email-oauth2/) and [WebAuthn and Passkeys](../../configuration/webauthn/) for login, email codes, and MFA dependencies.
      7. Read [Rate Limits and Connection Limits](../../configuration/rate-limits/) to understand protections for login, verification codes, WebSocket, and API requests.
      8. Read [Metrics Monitoring](../../configuration/metrics/) and [Observability Runbook](../../operations/observability/) before integrating Prometheus-compatible monitoring.
    </Steps>
  </TabItem>
  <TabItem label="Developer" icon="puzzle">
    <Steps>
      1. Read the [Development Guide](../development/) to prepare Rust, Node.js, PostgreSQL, Redis, SQLx, and the docs site.
      2. Read [OpenAPI Access](../../reference/openapi/) for Swagger UI and OpenAPI JSON locations.
      3. Read [gRPC Debugging](../../reference/grpc/) for cluster, admin, service protobuf, and reflection workflows.
      4. Read the [Client Integration Guide](../client-integration/) for login, MFA, WebSocket, OAuth2, and media header composition.
      5. Use the [Configuration Index](../../reference/configuration-index/) when changing configuration structs.
    </Steps>
  </TabItem>
</Tabs>

## Configuration Reading Order

The configuration pages are detailed. Read them by dependency and enabled feature, not as a single linear manual.

<CardGrid>
  <Card title="Core Runtime" icon="setting">
    <Badge text="Required" variant="tip" /> Start with server listener, runtime paths, security secrets, database, and Redis.
  </Card>
  <Card title="Access Control" icon="setting">
    Continue with CORS, trusted proxies, rate limits, email, OAuth2, WebAuthn, and user security settings.
  </Card>
  <Card title="Media Features" icon="puzzle">
    If media providers or proxy cache are enabled, read provider, cache/proxy, livestream, and WebRTC pages.
  </Card>
  <Card title="Horizontal Scaling" icon="cloud-download">
    For multi-replica deployments, read cluster, Redis, Helm, Ingress, HLS storage, and metrics pages.
  </Card>
</CardGrid>
