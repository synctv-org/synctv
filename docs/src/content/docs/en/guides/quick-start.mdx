## Default Path: Single-node Production Compose

The recommended first path is a production-ready single-node deployment: prebuilt image, explicit secrets, persistent env files, PostgreSQL/Redis volumes, and readiness verification. Development Compose is only for code changes or short local previews.

Start with single-node production Compose by default. Use the deployment section for Docker Compose, Helm, and cluster details only when you need Kubernetes, multiple replicas, or deeper deployment planning.

| Path | Use case | Starts | Production-ready |
| --- | --- | --- | --- |
| A. Single-node production Compose | Long-running service on one server or local host | PostgreSQL, Redis, SyncTV | Yes, with your own secrets and backups |
| B. Local evaluation | Quick UI and feature preview | PostgreSQL, Redis, SyncTV | No, uses development secrets |
| C. Local source run | Development and API debugging | PostgreSQL/Redis in Docker, SyncTV on host | No, development environment |

## A. Single-node Production Compose

**Prerequisites**

- Docker and Docker Compose are available.
- You have a persistent directory for Compose files, `.env.postgres`, `.env.synctv`, and volumes.
- You know the access URL; public deployments also need TLS and backup locations.

Required long-lived secrets:

| Environment variable | Purpose | Recommended generation |
| --- | --- | --- |
| `SYNCTV_JWT_SECRET` | Signs access and refresh tokens | `openssl rand -base64 32` |
| `SYNCTV_SECURITY_OPAQUE_SERVER_SETUP_SECRET` | Stable OPAQUE password-auth secret | `openssl rand -base64 48` |
| `SYNCTV_SECURITY_CREDENTIAL_ENCRYPTION_KEY` | Encrypts provider credentials; must be 64 hex chars | `openssl rand -hex 32` |
| `SYNCTV_BOOTSTRAP_ROOT_PASSWORD` | Initial root account password | Generate with a password manager |

<Aside type="caution">
`SYNCTV_SECURITY_OPAQUE_SERVER_SETUP_SECRET` and `SYNCTV_SECURITY_CREDENTIAL_ENCRYPTION_KEY` are long-lived secrets. Keep them stable across restarts, upgrades, and rollbacks.
</Aside>

<Steps>
1. Download the production Compose files into an empty directory:

   <Code
     code={[
       'mkdir synctv-compose',
       'cd synctv-compose',
       `curl -fsSLO ${dockerComposeFileUrl}`,
       `curl -fsSLO ${composePostgresEnvExampleUrl}`,
       `curl -fsSLO ${composeSynctvEnvExampleUrl}`,
       'mkdir -p scripts',
       `curl -fsSL ${composeInitScriptUrl} -o scripts/init-compose-env.sh`,
       'chmod +x scripts/init-compose-env.sh',
     ].join('\n')}
     lang="bash"
   />

2. Generate persistent `.env.postgres` and `.env.synctv`:

   ```bash
   ./scripts/init-compose-env.sh
   ```

3. Edit `.env.synctv` and set at least `SYNCTV_BOOTSTRAP_ROOT_PASSWORD`. If frontend and API use different origins, also set `SYNCTV_SERVER_CORS_ALLOWED_ORIGINS`.

4. Validate rendered Compose and start:

   ```bash
   docker compose config
   docker compose up -d
   ```

5. Check status and logs:

   ```bash
   docker compose ps
   docker compose logs -f synctv
   ```
</Steps>

Success means `docker compose config` has no missing variable errors, `synctv` is running or healthy, and readiness succeeds:

```bash
curl -fsS http://localhost:8080/health/ready
```

Open `http://localhost:8080` or your real entrypoint. The default root username is `root`; its password comes from `SYNCTV_BOOTSTRAP_ROOT_PASSWORD`.

Next:

- Complete the [Production Checklist](../../deployment/production-checklist/).
- Read <a href={englishComposeDeploymentDocsUrl}>Docker Compose Deployment</a> for file and volume details.
- Read [Server Listener and Runtime Paths](../../configuration/server-and-runtime/) for reverse proxy, CORS, management, and `data_dir`.

## B. Local Evaluation

Use this only for temporary evaluation or development preview. It uses built-in development secrets and is not suitable for public or long-running deployments.

**Prerequisites**

- Docker and Docker Compose are available.
- The SyncTV repository is cloned, and commands are run from the repository root.

<Steps>
1. Start development Compose:

   ```bash
   docker compose -f docker-compose.dev.yml up -d
   ```

2. Check containers:

   ```bash
   docker compose -f docker-compose.dev.yml ps
   ```

3. Verify readiness:

   ```bash
   curl -fsS http://localhost:8080/health/ready
   ```
</Steps>

Then open `http://localhost:8080` or run:

```bash
docker compose -f docker-compose.dev.yml exec synctv synctv system stats
```

## C. Local Source Run

**Prerequisites**

- Rust toolchain is available.
- Docker and Docker Compose are available.
- The repository is cloned.

<Steps>
1. Start dependencies only:

   ```bash
   docker compose -f docker-compose.dev.yml up -d postgres redis
   ```

2. Validate configuration:

   ```bash
   cargo run -p synctv --bin synctv -- config validate
   ```

3. Start SyncTV. Startup runs embedded SQLx migrations automatically:

   ```bash
   cargo run -p synctv --bin synctv -- serve
   ```

4. In another terminal, verify readiness:

   ```bash
   curl -fsS http://localhost:8080/health/ready
   ```
</Steps>

## First Login

When `bootstrap.create_root_user=true`, SyncTV creates a root user if the database does not already contain one.

Default username:

```yaml
bootstrap:
  root_username: "root"
```

Password sources:

- `bootstrap.root_password` in the config file.
- `SYNCTV_BOOTSTRAP_ROOT_PASSWORD`.
- `SYNCTV_BOOTSTRAP_ROOT_PASSWORD_FILE`.

Use environment variables or secret files in production. Do not commit the root password.

## Validate Configuration

With a local config file:

```bash
cargo run -p synctv --bin synctv -- config --config synctv.yaml validate
```

Validation checks YAML, secret strength, Redis/OAuth2/WebAuthn/cluster dependencies, and ranges for ports, paths, timeouts, and rate limits.
