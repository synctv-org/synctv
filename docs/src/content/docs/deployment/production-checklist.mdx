## 怎么用这份清单

这页用于上线前逐项确认，不是配置字段说明书。先完成“必须完成”，再根据规模完成“推荐完成”，最后按功能需要启用 WebAuthn、OAuth2、邮件、直播、HLS、STUN、slice cache 等能力。

如果你还没有理解整体组件边界，先读 [架构总览](../../guides/architecture/)。如果你正在设计登录、2FA、OAuth2 或管理控制面策略，先读 [认证与安全模型](../../guides/security-model/)。

## 必须完成

| 检查项 | 验收标准 |
| --- | --- |
| JWT secret | `jwt.secret` 通过 secret 机制注入，值不是示例值。 |
| OPAQUE setup secret | `security.opaque_server_setup_secret` 已生成、备份，并确认不会每次部署随机变化。 |
| 凭据加密 key | `security.credential_encryption_key` 已生成、备份，并且是 64 个十六进制字符。 |
| 初始 root 密码 | 来自 `SYNCTV_BOOTSTRAP_ROOT_PASSWORD` 或 secret file，没有提交到 Git。 |
| PostgreSQL 持久化 | 数据库使用持久化存储。 |
| PostgreSQL 备份 | 有备份策略，并至少知道恢复顺序。 |
| 配置校验 | `synctv config validate` 通过。 |
| 数据库 migration | `synctv db status` 或启动日志确认 embedded SQLx migrations 状态正常。 |
| 健康检查 | 服务启动后 `/health/ready` 返回成功。 |
| TLS | 对公网入口启用 TLS。 |
| 管理控制面 | 没有暴露给普通公网用户。 |

必填 secret 生成参考：

| Secret | 用途 | 生成方式 |
| --- | --- | --- |
| `jwt.secret` | 签发 access/refresh/guest token | `openssl rand -base64 32` |
| `security.opaque_server_setup_secret` | OPAQUE 密码认证 | `openssl rand -base64 48` |
| `security.credential_encryption_key` | 加密 Provider 凭据，64 个十六进制字符 | `openssl rand -hex 32` |
| `server.cluster_secret` | 集群节点间认证，集群模式必需 | `openssl rand -hex 32` |
| `bootstrap.root_password` | 首次 root 用户密码 | 密码管理器生成 |

<Aside type="caution">
OPAQUE setup secret 和 Provider 凭据加密 key 是长期密钥。丢失或随意轮换会影响现有密码记录或已保存 Provider 凭据。
</Aside>

## 推荐完成

| 检查项 | 验收标准 |
| --- | --- |
| Redis | 已配置 Redis，用于限流、token blacklist、OAuth2 state、WebAuthn challenge、L2 缓存和集群短期状态。 |
| Redis key prefix | `redis.key_prefix` 不和测试、预发或其他生产环境冲突。 |
| 日志 | 使用 JSON 日志或能被日志系统稳定解析的日志格式。 |
| Metrics 鉴权 | metrics 已启用，并配置 bearer/basic/Kubernetes 鉴权。 |
| Metrics 暴露面 | `/metrics` 没有直接暴露公网。 |
| 告警 | 覆盖 PostgreSQL、Redis、登录失败、MFA 失败、WebSocket、Provider、proxy、直播和集群。 |
| 反向代理/Ingress | 已配置合理超时并支持 WebSocket。 |
| 可信代理 | `server.trusted_proxies` 只信任你控制的代理网段。 |
| 滚动更新 | Kubernetes termination grace period 大于 `server.shutdown_drain_timeout_seconds`。 |
| 升级验证 | 测试环境验证 migration、登录、房间读写、实时连接和 Provider 访问。 |

## 按功能需要完成

| 功能 | 验收标准 |
| --- | --- |
| CORS | Web 前端和 API 不同 origin 时，配置 `server.cors_allowed_origins`，只填 origin，不带 path。 |
| Passkey/WebAuthn | 配置生产 `rp_id` 和 `rp_origin`，且必须匹配真实 HTTPS 访问入口。 |
| 邮件 | 使用邮箱验证、密码找回、邮箱 MFA 或系统通知时，配置 SMTP 并用 `synctv settings test-email` 测试。 |
| OAuth2 | 在 runtime settings 配置 provider，并确认 `redirect_url` 与第三方平台注册值一致。 |
| 多副本共享状态 | 所有副本共享同一个 PostgreSQL、Redis 和 `redis.key_prefix`。 |
| 集群模式 | 配置 `server.cluster_secret` 和 `server.advertise_host`。 |
| 公开 gRPC | Kubernetes 中拆分 HTTP Service/Ingress 和 gRPC Service/Ingress。 |
| 直播/STUN | 放行 RTMP 端口；使用内置 STUN 时，放行 UDP 3478。 |
| 多副本 HLS | 明确选择 publisher-node proxy、`shared_file` 或 OSS。 |
| 文件 slice cache | 挂载持久目录并确认容量、清理和共享策略。 |
| OpenAPI | 确认生产是否允许暴露 `/swagger-ui/` 和 `/api-docs/openapi.json`。 |

## 关键配置片段

### CORS 和可信代理

```yaml
server:
  cors_allowed_origins:
    - "https://app.example.com"
  trusted_proxies:
    - "10.0.0.0/8"
```

`cors_allowed_origins` 只填写 origin，例如 `https://app.example.com`。不要填写 `https://app.example.com/app`。

### WebAuthn/passkey

```yaml
webauthn:
  enabled: true
  rp_id: "example.com"
  rp_origin: "https://app.example.com"
```

`rp_origin` 必须是用户实际访问的 HTTPS origin。`rp_id` 必须是该 origin 的有效父域或同域。

### 邮件

```yaml
email:
  smtp_host: "smtp.example.com"
  smtp_port: 587
  smtp_username: "noreply@example.com"
  smtp_password_file: "/run/secrets/smtp_password"
  from_email: "noreply@example.com"
  from_name: "SyncTV"
  use_tls: true
```

测试命令：

```bash
synctv settings test-email admin@example.com
```

### gRPC Ingress

Nginx Ingress 的 gRPC Ingress 应设置：

```yaml
ingress:
  grpc:
    annotations:
      nginx.ingress.kubernetes.io/backend-protocol: "GRPC"
```

HTTP REST 和公开 gRPC 共享主进程端口，但 Kubernetes 中建议拆成两个 Service 和两个 Ingress，分别配置 TLS、路由和观测。

### HLS 存储

共享文件系统：

```yaml
livestream:
  hls_storage_backend: "shared_file"
  hls_storage_path: "/var/lib/synctv/hls"
```

对象存储：

```yaml
livestream:
  hls_storage_backend: "oss"
  hls_oss:
    endpoint: "https://s3.example.com"
    bucket: "synctv-hls"
    access_key_id_file: "/run/secrets/hls_oss_access_key_id"
    secret_access_key_file: "/run/secrets/hls_oss_secret_access_key"
```

### Proxy slice cache

```yaml
proxy_slice_cache:
  enabled: true
  file_backend_enabled: true
  file_cache_dir: "cache/proxy-slice"
```

slice cache 只缓存 Range 请求片段。上游不支持 Range 时会 bypass，不会缓存完整响应体。

### Metrics

```yaml
metrics:
  enabled: true
  auth:
    mode: "bearer_token"
    bearer_token_file: "/run/secrets/metrics_token"
```

不要把 `/metrics` 直接暴露公网。Kubernetes 中建议配合 ServiceMonitor、VMServiceScrape 或 NetworkPolicy。

## 上线验证命令

### 二进制或 systemd

```bash
synctv config validate
synctv db status
curl -fsS http://localhost:8080/health/ready
```

### Docker Compose

```bash
docker compose config
docker compose up -d
docker compose ps
docker compose exec synctv synctv db status
curl -fsS http://localhost:8080/health/ready
```

如果使用生产 Docker Compose，先按 [Docker Compose 部署](../docker-compose/#获取生产-compose-文件) 获取 `docker-compose.yml` 和 env 初始化脚本，并在 Compose 文件目录保存 `.env.postgres` 与 `.env.synctv`。

### Helm

```bash
helm lint ./helm/synctv
helm template synctv ./helm/synctv
helm status synctv -n synctv
kubectl -n synctv rollout status deploy/synctv
kubectl -n synctv get pods
```

## 备份

必须备份：

- PostgreSQL。
- 生产 secret。

按需备份：

- HLS `shared_file` 存储。
- proxy slice cache。
- 自定义配置文件。

通常不需要长期备份 Redis，但 Redis 重启会影响 OAuth2 state、token blacklist、限流计数、WebAuthn challenge 和集群短期状态。

详细恢复顺序和演练要求见 [备份与恢复](../../operations/backup-restore/)。

## 升级

升级前：

- 备份数据库。
- 保留所有 secret。
- 先在测试环境启动目标版本，验证自动 migration 和业务读写。
- 检查 [配置总索引](../../reference/configuration-index/)、[完整配置示例](../../configuration/full-example/)、Compose 和 Helm values 是否有新配置项。
- 如果启用 OpenAPI，确认客户端 SDK 与接口变更匹配。

Kubernetes 滚动更新时，设置合理的 readiness、termination grace period 和 `server.shutdown_drain_timeout_seconds`，避免大量长连接被突然断开。

详细 migration、Helm/Compose 发布、滚动更新和回滚策略见 [升级与迁移](../../operations/upgrades/)。
