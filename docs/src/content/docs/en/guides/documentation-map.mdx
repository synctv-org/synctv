This page organizes the documentation by task. It does not replace the configuration reference; it helps you decide which page to read first and what each section is meant to answer.

<Aside type="tip">
For a first deployment, follow the deployment path. For an existing service, jump directly to the task cards below.
</Aside>

## Reader Paths

<Tabs syncKey="reader-path">
  <TabItem label="Deployer" icon="rocket">
    <Steps>
      1. Start with [Quick Start](../quick-start/) and confirm the minimal Compose stack can boot.
      2. Read [Architecture Overview](../architecture/) to understand the main service, management, metrics, Redis, PostgreSQL, and provider proxy boundaries.
      3. Read [How Configuration Works](../../configuration/how-configuration-works/) to understand defaults, config files, environment variables, and CLI overrides.
      4. Start from the [Full Configuration Example](../../configuration/full-example/) minimal production skeleton, then copy feature sections from the full template as needed.
      5. Read [Security and Secrets](../../configuration/security/) to replace example secrets and keep long-lived keys stable across restarts and upgrades.
      6. Use [Docker Compose Deployment](../../deployment/docker-compose/) or [Helm Deployment](../../deployment/helm/) depending on your runtime.
      7. Before launch, run through the [Production Checklist](../../deployment/production-checklist/).
      8. Complete [Backup and Restore](../../operations/backup-restore/), [Upgrades and Migrations](../../operations/upgrades/), and [Observability Runbook](../../operations/observability/).
      9. If you are building a client, SDK, or third-party integration, read the [Client Integration Guide](../client-integration/).
      10. If you are designing data governance, privacy, or retention policy docs, read [Data, Privacy, and Retention](../../operations/data-retention/).
      11. For startup, Ingress, authentication, or media playback failures, start from [Troubleshooting](../../operations/troubleshooting/).
    </Steps>
  </TabItem>
  <TabItem label="Administrator" icon="setting">
    <Steps>
      1. Read the [CLI Reference](../../reference/cli/) for users, rooms, providers, system state, and configuration validation.
      2. Read [Administration Runbook](../administration/) to understand operational boundaries for users, rooms, reviews, providers, runtime settings, and system operations.
      3. Read [Rooms, Permissions, and Preferences](../rooms-permissions/) to understand global roles, room roles, permission bits, room settings, and user preferences.
      4. Read [Authentication and Security Model](../security-model/) to understand local login, OAuth2, 2FA, tokens, and the management control plane.
      5. Read [Runtime Settings Reference](../../reference/runtime-settings/) to know which policies are hot-reloadable and which require startup configuration.
      6. Read [Email and OAuth2](../../configuration/email-oauth2/) and [WebAuthn and Passkeys](../../configuration/webauthn/) for login, email codes, and MFA dependencies.
      7. Read [Rate Limits and Connection Limits](../../configuration/rate-limits/) to understand protections for login, verification codes, WebSocket, and API requests.
      8. Read [Metrics Monitoring](../../configuration/metrics/) and [Observability Runbook](../../operations/observability/) before integrating Prometheus-compatible monitoring.
    </Steps>
  </TabItem>
  <TabItem label="Developer" icon="puzzle">
    <Steps>
      1. Read the [Development Guide](../development/) to prepare Rust, Node.js, PostgreSQL, Redis, SQLx, and the docs site.
      2. Read [OpenAPI Access](../../reference/openapi/) for Swagger UI and OpenAPI JSON locations.
      3. Read [gRPC Debugging](../../reference/grpc/) for cluster, admin, service protobuf, and reflection workflows.
      4. Read the [Client Integration Guide](../client-integration/) for login, MFA, WebSocket, OAuth2, and media header composition.
      5. Use the [Configuration Index](../../reference/configuration-index/) when changing configuration structs.
    </Steps>
  </TabItem>
</Tabs>

## Configuration Reading Order

The configuration pages are detailed. Read them by dependency and enabled feature, not as a single linear manual.

<CardGrid>
  <Card title="Core Runtime" icon="setting">
    <Badge text="Required" variant="tip" /> Start with server listener, runtime paths, security secrets, database, and Redis.
  </Card>
  <Card title="Access Control" icon="setting">
    Continue with CORS, trusted proxies, rate limits, email, OAuth2, WebAuthn, and user security settings.
  </Card>
  <Card title="Media Features" icon="puzzle">
    If media providers or proxy cache are enabled, read provider, cache/proxy, livestream, and WebRTC pages.
  </Card>
  <Card title="Horizontal Scaling" icon="cloud-download">
    For multi-replica deployments, read cluster, Redis, Helm, Ingress, HLS storage, and metrics pages.
  </Card>
</CardGrid>

## Documentation Maintenance Checklist

- When adding a configuration field, update the [Configuration Index](../../reference/configuration-index/), the [Full Configuration Example](../../configuration/full-example/), and the matching configuration topic.
- When adding a CLI command, update the [CLI Reference](../../reference/cli/).
- When changing deployment templates, update [Docker Compose Deployment](../../deployment/docker-compose/) or [Helm Deployment](../../deployment/helm/).
- When changing common errors, ports, Ingress behavior, authentication, or proxy behavior, update [Troubleshooting](../../operations/troubleshooting/).
- When changing runtime surfaces, dependencies, provider/proxy boundaries, or cluster behavior, update [Architecture Overview](../architecture/).
- When changing login, 2FA, OAuth2, token, management, or permission boundaries, update [Authentication and Security Model](../security-model/).
- When changing users, rooms, reviews, providers, runtime settings, or management CLI semantics, update [Administration Runbook](../administration/).
- When changing room roles, permission bits, room settings, member overrides, or user preferences, update [Rooms, Permissions, and Preferences](../rooms-permissions/).
- When changing hot-reload fields registered in `SettingsRegistry`, update [Runtime Settings Reference](../../reference/runtime-settings/).
- When changing the OpenAPI feature, Swagger UI path, or OpenAPI JSON path, update [OpenAPI Access](../../reference/openapi/).
- When changing cluster, admin, or service protobuf files, update [gRPC Debugging](../../reference/grpc/).
