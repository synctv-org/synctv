## Email Configuration

`email` config controls SMTP delivery. It is used for:

- Email verification.
- Password reset.
- Email codes for MFA.
- System notifications.

If `email.smtp_host` is empty, email features are considered unavailable.

## SMTP Fields

| Field | Default | Purpose |
| --- | --- | --- |
| `email.smtp_host` | `""` | SMTP server host |
| `email.smtp_port` | `587` | SMTP server port |
| `email.smtp_username` | `""` | SMTP username |
| `email.smtp_password` | `""` | SMTP password or app password |
| `email.from_email` | `""` | Sender email address |
| `email.from_name` | `SyncTV` | Sender display name |
| `email.use_tls` | `true` | Whether to use TLS |

Example:

```yaml
email:
  smtp_host: "smtp.example.com"
  smtp_port: 587
  smtp_username: "synctv@example.com"
  smtp_password_file: "/run/secrets/smtp_password"
  from_email: "noreply@example.com"
  from_name: "SyncTV"
  use_tls: true
```

Common ports:

| Port | Meaning |
| --- | --- |
| `587` | STARTTLS, usually recommended |
| `465` | SMTPS |
| `25` | Traditional SMTP, often blocked by cloud providers |

Do not commit SMTP passwords. Use `smtp_password_file` or `SYNCTV_EMAIL_SMTP_PASSWORD_FILE`.

## OAuth2 and OIDC

`oauth2` config integrates third-party login providers such as GitHub, Google, Logto, Keycloak, Casdoor, Authelia, or other OIDC providers.

Important behavior:

- OAuth2 tokens are used only during login exchange and are not stored long-term.
- SyncTV stores the mapping between a local user and the external provider identity.
- OAuth2 does not participate in local 2FA, but users with 2FA enabled may still log in through OAuth2.

## `oauth2.redirect_scheme`

Purpose: scheme used when generating or validating OAuth2 redirect-related URLs.

Use HTTPS in production:

```yaml
oauth2:
  redirect_scheme: "https"
```

## `oauth2.providers`

Providers are dynamic objects. Each key is an instance name.

GitHub:

```yaml
oauth2:
  redirect_scheme: "https"
  providers:
    github:
      client_id: "your_github_client_id"
      client_secret_file: "/run/secrets/github_client_secret"
      redirect_url: "https://app.example.com/oauth2/callback"
```

Google:

```yaml
oauth2:
  providers:
    google:
      client_id: "your_google_client_id"
      client_secret_file: "/run/secrets/google_client_secret"
      redirect_url: "https://app.example.com/oauth2/callback"
```

Generic OIDC:

```yaml
oauth2:
  providers:
    keycloak:
      type: oidc
      client_id: "synctv"
      client_secret_file: "/run/secrets/keycloak_client_secret"
      issuer: "https://keycloak.example.com/realms/main"
      redirect_url: "https://app.example.com/oauth2/callback"
```

Logto:

```yaml
oauth2:
  providers:
    logto:
      type: logto
      client_id: "synctv"
      client_secret_file: "/run/secrets/logto_client_secret"
      endpoint: "https://logto.example.com"
      redirect_url: "https://app.example.com/oauth2/callback"
```

## Provider Fields

`client_id` is the application ID assigned by the provider. It is not usually a secret.

`client_secret` is sensitive. Prefer:

```yaml
client_secret_file: "/run/secrets/provider_client_secret"
```

`redirect_url` is the callback URL used by the frontend or native client. SyncTV uses a frontend/client-driven flow:

1. The provider redirects the user to the frontend or native client callback with `code` and `state`.
2. The frontend or client calls SyncTV's exchange endpoint.

Examples:

- Web frontend: `https://app.example.com/oauth2/callback`
- Desktop or mobile app: `synctv://oauth2/callback`

## Redis Dependency

OAuth2 login needs temporary state storage. Single-node deployments can use memory state when Redis is unavailable.

Multi-replica deployments must use Redis. Otherwise the initial login request and callback exchange may hit different Pods and the state may not be found.
