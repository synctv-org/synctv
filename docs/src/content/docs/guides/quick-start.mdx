## 默认选择：单机生产 Compose

SyncTV 的推荐入门路径是单机生产可用部署：使用预构建镜像、显式 secret、持久化 env 文件、PostgreSQL/Redis 数据卷和 readiness 验收。开发 Compose 只适合改代码或临时本地试用，不作为默认路径。

默认从单机生产 Compose 开始。只有需要 Kubernetes、多副本或更细的部署模型时，才进入部署章节阅读 Docker Compose、Helm 和集群配置。

| 路径 | 适合场景 | 会启动什么 | 是否可用于生产 |
| --- | --- | --- | --- |
| A. 单机生产 Compose | 在一台服务器或本机长期运行 | PostgreSQL、Redis、SyncTV | 是，需要自管 secret 和备份 |
| B. 本地试用 | 只想快速看界面和功能 | PostgreSQL、Redis、SyncTV | 否，内置开发 secret |
| C. 本机源码运行 | 参与开发、调试 API 或改代码 | Docker 中的 PostgreSQL/Redis，加本机 SyncTV | 否，开发环境 |

## A. 单机生产 Compose

**前置条件**

- Docker 和 Docker Compose 可用。
- 已准备一个持久化目录保存 Compose 文件、`.env.postgres`、`.env.synctv` 和数据卷。
- 知道你的访问地址；公网部署时还需要 TLS 入口和备份位置。

**必须长期保存的 secret**

| 环境变量 | 用途 | 推荐生成方式 |
| --- | --- | --- |
| `SYNCTV_JWT_SECRET` | 签发访问 token 和刷新 token | `openssl rand -base64 32` |
| `SYNCTV_SECURITY_OPAQUE_SERVER_SETUP_SECRET` | OPAQUE 密码认证的稳定服务端 secret | `openssl rand -base64 48` |
| `SYNCTV_SECURITY_CREDENTIAL_ENCRYPTION_KEY` | 加密 Provider 凭据，必须是 64 个十六进制字符 | `openssl rand -hex 32` |
| `SYNCTV_BOOTSTRAP_ROOT_PASSWORD` | 第一次启动时创建 root 用户的密码 | 使用密码管理器生成强密码 |

<Aside type="caution">
`SYNCTV_SECURITY_OPAQUE_SERVER_SETUP_SECRET` 和 `SYNCTV_SECURITY_CREDENTIAL_ENCRYPTION_KEY` 不是一次性启动密码。它们必须跨重启、升级和回滚保持稳定。
</Aside>

**启动**

<Steps>
1. 在空目录下载生产 Compose 所需文件：

   <Code
     code={[
       'mkdir synctv-compose',
       'cd synctv-compose',
       `curl -fsSLO ${dockerComposeFileUrl}`,
       `curl -fsSLO ${composePostgresEnvExampleUrl}`,
       `curl -fsSLO ${composeSynctvEnvExampleUrl}`,
       'mkdir -p scripts',
       `curl -fsSL ${composeInitScriptUrl} -o scripts/init-compose-env.sh`,
       'chmod +x scripts/init-compose-env.sh',
     ].join('\n')}
     lang="bash"
   />

2. 生成持久化 `.env.postgres` 和 `.env.synctv`：

   ```bash
   ./scripts/init-compose-env.sh
   ```

3. 编辑 `.env.synctv`，至少设置 `SYNCTV_BOOTSTRAP_ROOT_PASSWORD`。如果前端和 API 不同 origin，同时设置 `SYNCTV_SERVER_CORS_ALLOWED_ORIGINS`。

4. 先检查渲染结果，再启动：

   ```bash
   docker compose config
   docker compose up -d
   ```

5. 查看状态和日志：

   ```bash
   docker compose ps
   docker compose logs -f synctv
   ```
</Steps>

**成功后应该看到**

- `docker compose config` 不再报 required variable missing。
- `docker compose ps` 中 `synctv` 为 running 或 healthy。
- readiness 成功：

  ```bash
  curl -fsS http://localhost:8080/health/ready
  ```

- 浏览器可以打开 `http://localhost:8080` 或你的真实入口。
- root 用户名默认是 `root`，密码来自 `.env.synctv` 中的 `SYNCTV_BOOTSTRAP_ROOT_PASSWORD`。

**下一步**

- 按 [生产部署清单](../../deployment/production-checklist/) 补齐 TLS、备份、metrics、告警和升级策略。
- 需要解释 Compose 文件和数据卷时读 <a href={composeDeploymentDocsUrl}>Docker Compose 部署</a>。
- 配置反向代理、CORS、management 和 `data_dir` 时读 [服务监听与运行时路径](../../configuration/server-and-runtime/)。

## B. 本地试用

这条路径只用于临时体验或开发前预览。它会使用开发 Compose 内置 secret，不要用于公网或长期运行。

**前置条件**

- Docker 和 Docker Compose 可用。
- 已 clone SyncTV 仓库，并在仓库根目录执行命令。

<Steps>
1. 启动开发 Compose：

   ```bash
   docker compose -f docker-compose.dev.yml up -d
   ```

2. 查看容器状态：

   ```bash
   docker compose -f docker-compose.dev.yml ps
   ```

3. 验证 readiness：

   ```bash
   curl -fsS http://localhost:8080/health/ready
   ```
</Steps>

成功后，浏览器可以打开 `http://localhost:8080`，也可以执行：

```bash
docker compose -f docker-compose.dev.yml exec synctv synctv system stats
```

## C. 本机源码运行

**前置条件**

- Rust toolchain 可用。
- Docker 和 Docker Compose 可用。
- 已 clone 仓库，并在仓库根目录执行命令。

<Steps>
1. 只启动依赖服务：

   ```bash
   docker compose -f docker-compose.dev.yml up -d postgres redis
   ```

2. 校验当前配置：

   ```bash
   cargo run -p synctv --bin synctv -- config validate
   ```

3. 启动 SyncTV。启动阶段会自动执行 embedded SQLx migrations：

   ```bash
   cargo run -p synctv --bin synctv -- serve
   ```

4. 另开终端检查 readiness：

   ```bash
   curl -fsS http://localhost:8080/health/ready
   ```
</Steps>

成功后可以继续读：

- [OpenAPI 文档入口](../../reference/openapi/)
- [gRPC 调试](../../reference/grpc/)
- [配置文件如何工作](../../configuration/how-configuration-works/)

## 第一次登录

当 `bootstrap.create_root_user=true` 时，SyncTV 会在数据库还没有 root 用户时创建一个 root 账号。

默认用户名：

```yaml
bootstrap:
  root_username: "root"
```

密码来源按优先级来自：

- 配置文件里的 `bootstrap.root_password`
- 环境变量 `SYNCTV_BOOTSTRAP_ROOT_PASSWORD`
- 文件变量 `SYNCTV_BOOTSTRAP_ROOT_PASSWORD_FILE`

生产环境建议只用环境变量或 secret 文件，不要把 root 密码写进公开仓库。

## 配置验证

如果使用本地 `synctv.yaml`：

```bash
cargo run -p synctv --bin synctv -- config --config synctv.yaml validate
```

它会检查 YAML、secret 强度、Redis/OAuth2/WebAuthn/集群依赖关系，以及端口、路径、超时、限流等数值是否合理。
