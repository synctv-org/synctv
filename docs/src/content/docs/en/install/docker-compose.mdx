This method uses prebuilt images to run SyncTV, PostgreSQL, and Redis on one server, NAS, or virtual machine. Kubernetes environments use the [Helm deployment](../helm/).

If you have not chosen a deployment model yet, start with [Choose a Deployment Path](../choose-path/).

## Prerequisites

- Docker and Docker Compose.
- GNU Make and `openssl` for environment-file and secret generation.
- A durable working directory for the Compose configuration, environment files, and volumes.
- An initial root password generated by a password manager.

## Install

<Steps>
1. Get the production Compose configuration:

    <Code code={`git clone --depth 1 ${githubCloneUrl} synctv\ncd synctv`} lang="bash" />

2. Generate `.env.postgres`, `.env.redis`, and `.env.synctv`:

    ```bash
    make compose-init
    ```

3. Edit `.env.synctv` and set the initial root password. Add the CORS origin when the frontend and API use different origins:

    ```dotenv
    SYNCTV_BOOTSTRAP_ROOT_PASSWORD=replace-with-a-strong-password
    SYNCTV_SERVER_CORS_ALLOWED_ORIGINS=["https://app.example.com"]
    ```

4. Validate the final Compose configuration:

    ```bash
    make compose-config
    ```

5. Start the services in the background:

    ```bash
    make compose-up
    ```
</Steps>

`make compose-init` uses `openssl` to generate PostgreSQL, Redis, JWT, cluster, credential-encryption, and OPAQUE secrets. PostgreSQL and Redis passwords use a URL-safe hexadecimal format. Compose uses <code>{dockerImageReference}</code> by default.

## Verify

Inspect the containers and request the readiness endpoint:

```bash
make compose-ps
curl -fsS http://localhost:8080/health/ready
```

Open `http://localhost:8080` in a browser. The default root username is `root`; the password comes from `SYNCTV_BOOTSTRAP_ROOT_PASSWORD` in `.env.synctv`.

## Environment Files and Versions

Docker Compose loads required `.env.postgres`, `.env.redis`, and `.env.synctv` files through `env_file`: PostgreSQL reads only database variables, Redis reads only `REDIS_PASSWORD`, and `synctv` reads only `SYNCTV_*` application settings. `make compose-init` writes the same generated Redis password into `.env.redis` as `REDIS_PASSWORD` and into `.env.synctv` inside the authenticated `SYNCTV_REDIS_URL`. Back up all three files and reuse them across restarts, new shells, host reboots, and upgrades. A missing file causes `make compose-config` to fail immediately.

When upgrading, set `SYNCTV_IMAGE_TAG` to the desired release before running Compose, or pin the desired image in your own Compose override file. The sample Compose file defaults to the documented app version instead of `latest` so deployments are reproducible. Treat PostgreSQL and Redis image tag changes as separate data-service upgrades: back up the volumes first, review upstream release notes, and keep rollback tags available.

## Volumes

Compose uses volumes for:

- PostgreSQL data.
- Redis data.
- SyncTV `/data` runtime directory.

`/data` corresponds to:

```bash
SYNCTV_DATA_DIR=/data
```

This directory may contain:

- Management socket runtime files.
- HLS files.
- Proxy slice cache files.
- Other runtime-owned outputs.

## Ports

Default exposed ports:

| Host port | Container port | Purpose |
| --- | --- | --- |
| `8080` | `8080` | HTTP REST + gRPC + health checks |
| `1935` | `1935` | RTMP |
| `3478/udp` | `3478/udp` | STUN |

If a host port conflicts, edit the Compose port mapping.

## Backups

Back up the PostgreSQL volume, all three environment files, and `/data` when persistent HLS or proxy slice cache is enabled. Preserve these values for the lifetime of the installation:

| Environment variable | Purpose |
| --- | --- |
| `SYNCTV_JWT_SECRET` | Signs access, refresh, and guest tokens |
| `SYNCTV_SECURITY_OPAQUE_SERVER_SETUP_SECRET` | Long-lived server secret for OPAQUE password authentication |
| `SYNCTV_SECURITY_CREDENTIAL_ENCRYPTION_KEY` | Encrypts Provider credentials |
| `SYNCTV_BOOTSTRAP_ROOT_PASSWORD` | Creates the initial root user |

<Aside type="caution">
Reuse the secrets in `.env.synctv` for the lifetime of the installation. Existing password records depend on the OPAQUE secret, and Provider credentials depend on the credential encryption key.
</Aside>

Redis stores cache and shared state. Restoring or clearing Redis affects short-lived OAuth2 state, token blacklist entries, and rate-limit counters.

## Common Failures

| Symptom | Action |
| --- | --- |
| `make compose-config` reports missing variables or files | Run `make compose-init` and keep all three environment files in the current directory. |
| `/health/ready` fails | Run `make compose-logs SERVICE=synctv` and inspect the first startup error. |
| The browser reports a CORS error | Set `SYNCTV_SERVER_CORS_ALLOWED_ORIGINS` in `.env.synctv` as an array of origins. |
| The root user cannot sign in | Confirm the root password was set before the first database startup and inspect bootstrap logs. |
| A host port is already in use | Change the Compose port mapping, then run `make compose-config` again. |
