## SyncTV 是什么

SyncTV 是一个可以自托管的多人同步观影和媒体协作服务。你可以把它理解成一个独立的 Watch Party 后端：用户进入房间后共享播放状态、聊天、弹幕和成员权限；管理员可以接入多个媒体 Provider，按需要启用代理、slice cache、直播、OAuth2、WebAuthn、metrics 和多节点集群。

它既可以作为个人或小团队的单机服务运行，也可以部署成多副本生产集群。

## 推荐最快路径：单机生产 Compose

默认先按单机生产可用模式启动：下载生产 Compose 文件，生成持久化 env，显式设置 root 密码和长期 secret，再启动服务。

<Aside type="tip">
长期运行的默认答案是单机生产 Compose。需要 Kubernetes 或多副本时，再进入部署章节阅读 Helm 和集群配置。
</Aside>

<Code
  code={[
    'mkdir synctv-compose',
    'cd synctv-compose',
    `curl -fsSLO ${dockerComposeFileUrl}`,
    `curl -fsSLO ${composePostgresEnvExampleUrl}`,
    `curl -fsSLO ${composeSynctvEnvExampleUrl}`,
    'mkdir -p scripts',
    `curl -fsSL ${composeInitScriptUrl} -o scripts/init-compose-env.sh`,
    'chmod +x scripts/init-compose-env.sh',
    './scripts/init-compose-env.sh',
  ].join('\n')}
  lang="bash"
/>

然后编辑 `.env.synctv`，至少设置：

```dotenv
SYNCTV_BOOTSTRAP_ROOT_PASSWORD=replace-with-a-strong-password
```

保存后再启动并验证：

<Code
  code={[
    'docker compose config',
    'docker compose up -d',
    'curl -fsS http://localhost:8080/health/ready',
  ].join('\n')}
  lang="bash"
/>

成功后打开：

```text
http://localhost:8080
```

这条路径使用预构建镜像和持久化 env 文件，适合单机长期运行。生产部署必须长期保存 `jwt.secret`、`security.opaque_server_setup_secret`、`security.credential_encryption_key` 和 root 密码。

<Aside type="tip">
第一次接触 SyncTV 时，也优先走单机生产 Compose。只想临时看界面时，再使用快速开始里的开发 Compose 路径。
</Aside>

## 必须先理解的少数概念

这些概念会在后续页面反复出现：

- **PostgreSQL**：唯一必须持久化的业务数据源。
- **Redis**：共享短期状态、限流、OAuth2 state、WebAuthn challenge、L2 缓存和集群协调；单机可选，生产推荐，多副本必需。
- **Provider**：把外部媒体源解析成可播放 URL 或 SyncTV 代理 URL 的适配层。
- **management gRPC**：CLI 和运维命令使用的管理控制面，不应暴露给普通客户端。
- **OPAQUE setup secret**：密码认证协议的服务端长期 secret，不能每次部署随机变化。
- **slice cache**：只缓存 Range 请求片段，不缓存完整文件。

更多短定义见 [术语速查](reference/glossary/)。
