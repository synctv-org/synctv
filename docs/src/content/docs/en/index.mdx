## What SyncTV Is

SyncTV is a self-hosted synchronized watching and media collaboration service. Think of it as an independent Watch Party backend: users join rooms with shared playback state, chat, danmaku, membership, and permissions. Administrators can attach media providers and enable proxying, slice cache, livestreaming, OAuth2, WebAuthn, metrics, and multi-node clustering as needed.

It can run as a simple single-node service or as a multi-replica production cluster.

## Recommended Fastest Path: Single-node Production Compose

Start with the production-ready single-node path: download production Compose files, generate persistent env files, explicitly set the root password and long-lived secrets, then start the service.

<Aside type="tip">
The default answer for a long-running service is single-node production Compose. Use the deployment section for Helm and cluster deployment details when you need Kubernetes or multiple replicas.
</Aside>

<Code
  code={[
    'mkdir synctv-compose',
    'cd synctv-compose',
    `curl -fsSLO ${dockerComposeFileUrl}`,
    `curl -fsSLO ${composePostgresEnvExampleUrl}`,
    `curl -fsSLO ${composeSynctvEnvExampleUrl}`,
    'mkdir -p scripts',
    `curl -fsSL ${composeInitScriptUrl} -o scripts/init-compose-env.sh`,
    'chmod +x scripts/init-compose-env.sh',
    './scripts/init-compose-env.sh',
  ].join('\n')}
  lang="bash"
/>

Then edit `.env.synctv` and set at least:

```dotenv
SYNCTV_BOOTSTRAP_ROOT_PASSWORD=replace-with-a-strong-password
```

After saving the file, start and verify:

<Code
  code={[
    'docker compose config',
    'docker compose up -d',
    'curl -fsS http://localhost:8080/health/ready',
  ].join('\n')}
  lang="bash"
/>

Then open:

```text
http://localhost:8080
```

This path uses the prebuilt image and persistent env files, and is suitable for long-running single-node deployments. Production deployments must preserve `jwt.secret`, `security.opaque_server_setup_secret`, `security.credential_encryption_key`, and the root password.

<Aside type="tip">
Even for first-time use, prefer single-node production Compose. Use the development Compose path only for temporary UI preview or code work.
</Aside>

## Concepts To Know First

- **PostgreSQL**: the durable business data store.
- **Redis**: shared short-lived state, rate limits, OAuth2 state, WebAuthn challenges, L2 cache, and cluster coordination. Optional for simple single-node mode, recommended in production, required for multi-replica mode.
- **Provider**: resolves external media into a playable URL or a SyncTV proxy URL.
- **management gRPC**: the control plane used by CLI and operations commands; do not expose it to normal clients.
- **OPAQUE setup secret**: long-lived server secret for password authentication; do not regenerate it on every deployment.
- **slice cache**: caches Range slices, not whole files.

See [Glossary](reference/glossary/) for short definitions.
