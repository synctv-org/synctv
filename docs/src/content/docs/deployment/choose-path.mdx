## 先选路径，再复制命令

SyncTV 的默认推荐是 **单机生产 Compose**。它适合第一次部署，也适合一台服务器上的长期运行。只有在你明确需要改代码、临时体验，或已经有 Kubernetes 平台时，才选择其他路径。

## 路径对比

| 路径 | 适合谁 | 启动方式 | 生产可用性 | 下一页 |
| --- | --- | --- | --- | --- |
| 单机生产 Compose | 自托管用户、小团队、一台服务器 | 预构建镜像 + `.env.postgres` + `.env.synctv` | 推荐默认路径 | [快速开始](../../guides/quick-start/) |
| 本地试用 | 只想临时看界面或功能 | `docker-compose.dev.yml` | 不可用于公网或长期运行 | [快速开始：本地试用](../../guides/quick-start/#b-本地试用) |
| 源码运行 | 开发者、调试 API、改代码 | 容器依赖 + 本机 `cargo run` | 不作为部署方式 | [开发指南](../../guides/development/) |
| Helm/Kubernetes | 多副本、平台团队、统一 Ingress/监控 | Helm values + Kubernetes Secret/PVC/Ingress | 可用于生产，但复杂度更高 | [Helm 部署](../helm/) |

## 默认路径：单机生产 Compose

选择它，如果你符合任一条件：

- 只有一台服务器或一台 NAS/VM。
- 想尽快得到一个长期可用的 SyncTV 实例。
- 不想先理解 Kubernetes、Ingress controller、PVC、Secret operator。
- 可以自己管理 PostgreSQL 备份和几个长期 secret。

成功标准：

- `.env.postgres` 和 `.env.synctv` 已持久保存并备份。
- `docker compose config` 通过。
- `/health/ready` 返回 200。
- root 用户可以登录。
- PostgreSQL 有备份方案。

## 什么时候不选默认路径？

<CardGrid>
  <Card title="只想临时体验" icon="rocket">
    使用本地试用。它启动快，但内置开发 secret，不应暴露公网，也不应长期运行。
  </Card>
  <Card title="要改代码" icon="puzzle">
    使用源码运行。PostgreSQL 和 Redis 可以仍由开发 Compose 提供，SyncTV 本体由本机 Rust 工具链启动。
  </Card>
  <Card title="已有 Kubernetes 平台" icon="cloud-download">
    使用 Helm。先明确 HTTP/gRPC Ingress、Secret、PVC、metrics、Redis、HLS 存储和滚动更新边界。
  </Card>
  <Card title="需要多副本实时协作" icon="setting">
    使用 Helm 或自管多副本部署，并开启集群配置。所有副本必须共享 PostgreSQL、Redis 和一致的 cluster secret。
  </Card>
</CardGrid>

## 决策底线

<Steps>
1. 只要对外提供服务，就不要使用开发 Compose 的内置 secret。
2. 只要长期运行，就必须备份 PostgreSQL 和生产 secret。
3. 只要多副本运行，就必须共享 PostgreSQL、Redis、`redis.key_prefix` 和 `server.cluster_secret`。
4. 只要启用 HLS 多副本，就必须选择 publisher-node proxy、`shared_file` 或 OSS 之一。
5. 只要管理控制面使用 TCP，就必须配置 token，并避免暴露给普通公网入口。
</Steps>

<Aside type="tip">
如果还不确定，选单机生产 Compose。它是最小的生产闭环，后续仍可以迁移到 Helm 或其他编排系统。
</Aside>
